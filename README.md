# スイッチ — Riot / League of Legends アカウント切り替えツール

システムトレイに常駐し、**Riot のセッションファイルを入れ替える方式**で複数アカウントを
ワンクリックで切り替える Windows 用アプリです。切り替えたあと、そのままゲームまで起動します。

保存済みのセッションが無効になっていた場合は、Riot Client のログイン画面へ
ID とパスワードを自動入力してサインインし直します。

---

## 主な機能

- **アカウント切り替え＋ゲーム起動** — 一覧の**シングルクリックで LoL**、**ダブルクリックで VALORANT**（MENU のトグルでOFFにすると切り替えるだけ）
- **切り替え中でも操作できる** — 待っている間もトレイは反応し、**中止も終了もいつでもできます**。押し間違えたら「取り消し」で戻せます
- **自動ログイン** — セッションが切れていたら、ログイン欄へ自動入力してサインイン
- **アカウント新規登録** — ID / パスワードを登録すると、初回ログイン後にセッションを自動保存
- **ランク表示** — 各アカウントのソロランク（例: `D2`, `G4`）をボタンに表示（Riot API・1時間キャッシュ）
- **PUUID の自動記録** — API キーがあれば PUUID を自動取得してメモに追記（取得済みはスキップ）
- **PUUID ⇄ Riot ID 変換ツール** — Riot API で相互変換、履歴保存
- **ログイン中の表示** — 今ログインしているアカウントの行に印が付きます
- **並べ替え** — 長押しして掴み、好きな順に並べられます
- **ライト / ダークモード** — MENU のトグルで切り替え、設定は保存されます
- **多重起動防止** — 常に1インスタンスのみ

---

## 動作要件

- Windows 10 / 11
- Riot Client がインストール済み（League of Legends / VALORANT のどちらでも）
- **ライセンス認証** — 起動のたびに認証を行い、通らない場合は理由とマシンコードを表示して終了します（後述）
- **ソースから実行する場合**は Python 3.x と以下のパッケージ

```bash
pip install PyQt6 requests urllib3 pyautogui pywin32 uiautomation comtypes
```

> `pyautogui` はログイン情報のキー入力に使います。`uiautomation` / `comtypes` は
> 入力欄へ直接値を差し込む方式に使いますが、**今の Riot Client ではこの方式は通りません**（後述）。

### ライセンス認証

起動時に一度だけ確認します。動きは次のとおりです。

- ホワイトリストに載っている機体は、常に許可（枠を消費しません）
- 一度認証できたら結果を `license.dat` に覚え、**3日間はオンライン確認をしません**
- 3日を過ぎたら再確認します。通信できなくても、**最後に成功してから7日以内なら起動できます**
- 認証できなかった場合は、理由とマシンコードを出すダイアログだけが出て終了します

## セットアップ

### API キー（ランク表示・PUUID ツールを使う場合のみ）

[Riot Developer Portal](https://developer.riotgames.com/) で取得したキーを `.env` に書きます。

```
RIOT_API_KEY=RGAPI-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

`.env` は以下のどちらでも読み込まれます（**exe の隣が最優先**）。

1. `スイッチ.exe`（またはソース）と同じフォルダ
2. `%LOCALAPPDATA%\Switch\.env`

- API キーが無くても**アカウント切り替えとゲーム起動は動きます**。効かなくなるのは
  ランク表示・PUUID の自動記録・PUUID ツールの3つです
- **ランクの問い合わせ先は日本サーバー（`jp1`）固定**です。JP 以外のアカウントは
  ランクが取得できません（アカウント自体の検索は `asia` を使うので、PUUID は取れます）

## 使い方

タスクトレイのアイコンを操作します。

| 操作 | 動作 |
|---|---|
| **左クリック** | 登録アカウント一覧を表示 |
| **右クリック** | MENU を表示 |
| アカウントを**シングルクリック** | そのアカウントに切り替えて **League of Legends** を起動 |
| アカウントを**ダブルクリック** | そのアカウントに切り替えて **VALORANT** を起動 |
| アカウントを**右クリック** | 操作パネル（メモ / ID・PW のコピー / 変更 / 削除）を表示 |
| アカウントを**長押しして上下に動かす** | 並べ替え（離した時点で保存） |
| **＋ アカウントを追加** | ID・パスワードを入力して新規登録 |

一覧を開くと、**今ログインしているアカウントの行に印**が付きます（背景がわずかに濃くなり、
右端に青い点）。判定は Riot Client のローカル API（`chat/v1/session`）に問い合わせますが、
**別スレッドで行う**のでメニューの表示は待たされません。

ランクは一覧を開いたときに更新します。ただし**1時間キャッシュ**しているので、
期限が切れたアカウントだけを取りに行きます（API キーが無ければ何もしません）。

### MENU の中身（右クリック）

| 項目 | 動作 |
|---|---|
| PUUID ツール | Riot ID ⇄ PUUID の相互変換と履歴 |
| 設定 (メモ帳) | `settings.json` をメモ帳で開く |
| CPUログを開く | `cpu_watchdog.log` を開く |
| 診断ログを開く | `debug_log.txt` を開く |
| **クリックで起動**（トグル） | 一覧のクリックでゲームまで起動するか |
| **ダークモード**（トグル） | ライト / ダークの切り替え |
| 終了 | アプリを終了 |

## ゲームの起動

一覧のクリックで、切り替えたあとそのままゲームが起動します。

| 操作 | 起動するもの |
|---|---|
| シングルクリック | League of Legends |
| ダブルクリック | VALORANT |

- ダブルクリックか判別するため、**シングルクリックはWindowsのダブルクリック判定間隔
  （通常0.5秒）だけ待ってから**動き出します
- 掴んで並べ替えたときは、クリック扱いになりません
- ログインの完了を確認できないまま60秒たった場合は、**起動を取りやめます**

### クリックで起動 を OFF にすると

MENU のトグルでOFFにすると、**シングルもダブルも「切り替えるだけ」**になります。
設定は `settings.json` の `"click_launch"` に保存されます（既定は `true`）。

OFFのときはダブルクリックを見極める必要がないので、**待たずに**すぐ切り替わります
（実測 634ms → 1ms）。

### どうやって起動しているか

Riot Client の「プレイ」ボタンは、押されるとクライアント自身のローカル API を叩いています。
そこへ同じ依頼を出すことで、**画面もマウスも触らずに**ゲームを起動します。

```
POST https://127.0.0.1:<port>/product-launcher/v1/products/<product>/patchlines/live?clickWallMs=<今の時刻ms>
Authorization: Basic riot:<lockfileのパスワード>
→ 200 "<セッションID>"
```

`<port>` とパスワードは `Riot Client/Config/lockfile` にあり、クライアントを起動し直すたびに
変わるので、**使う直前に毎回読み直します**。

- 依頼の前に `.../live/eligibility` を 0.25 秒おきに見て、受け付けられるようになった瞬間に投げます。
  **15秒**待っても立たない場合は、それでも投げてみます
- 依頼が通ったら、あとはクライアントの仕事です。最大45秒プロセスの出現を見届けます。
  現れなくても「更新の適用中かもしれません」として終わります（失敗扱いにはしません）
- 断られた場合の保険として `--launch-product`（公式ショートカットと同じ引数）と、
  ゲーム本体の直接起動を順に試します。ただし前者は製品ページを開くだけ、後者は
  Vanguard に弾かれるのが普通なので、あくまで保険です
- なお切り替えでクライアントを立ち上げ直すときは、最初からこの引数を付けています
  （目的のゲームのページが開いた状態になります）

### 速さ（実測）

同じ実機・同じクライアントで、切り替えの開始からロビーのプロセスが立つまで。

| | 変更前 | 変更後 |
|---|---:|---:|
| 別のアカウントへ切り替えて起動 | 9.4秒 | **7.8秒** |
| 今ログイン中のアカウントで起動 | 9.4秒 | **3.9秒** |

- **既にそのアカウントでログイン済みなら、クライアントを落として立て直しません**。
  再起動と認証だけで4.5秒かかるので、そこを丸ごと省きます（判定はローカルAPIに
  1回訊くだけで0.1秒ほど）
- プロセスの確認を `tasklist` から Toolhelp のスナップショットに変えました。
  1回 **482ms → 9ms** で、起動待ちの間ずっと毎秒叩いていたぶんのCPUも無くなります
- 終了待ちの一律1秒をやめ、消えた時点で次へ進みます（最大5秒。過ぎたら警告を出して続行）

残りの約7.8秒はほぼ Riot 側の時間です（クライアント起動〜認証に3.2秒、起動依頼の処理に3.7秒）。
`--launch-background-mode` で軽く立ち上げる案も試しましたが、そのモードでは起動の窓口が
最後まで用意されず（150秒間ずっと404）、使えませんでした。

## 切り替えの流れ

1. 押し間違い用に**1秒だけ何もしない**（ここで取り消せば本当に何も起きません）
2. 既にそのアカウントでログイン済みなら、ここで終わり（ゲームだけ起動）
3. Riot のプロセスを終了
4. 控えのセッションファイルを実機へコピー
5. Riot Client を起動
6. 認証されたかローカル API で確認
7. 認証されていなければ、ログイン画面へ自動入力（後述）

### 切り替え中でも操作できる

切り替えは**別スレッド**で進みます。待っている間もアプリは動き続けるので、
トレイを押せばいつでもこの画面が出ます。

```
処理中
  フェイトソード#TBH に切り替え中
  中止する
  ─────────
  終了
```

**「終了」がいつでも効く**のが肝心です（進行中の切り替えを中止してから閉じます）。
新規アカウントの追加中は、2行目が「アカウントを追加中」になります。

### 押し間違えたとき

アカウントを押すと右下にこう出ます。

```
フェイトソード#TBH に切り替えます        取り消し
```

- **最初の1秒**（`GRACE_SEC`）に押せば、本当に何も起きていない状態で止まります
- そのあと**ファイルを入れ替えるまで**の間（プロセスの終了待ち中）に押した場合も、
  まだ切り替わっていません
- ファイルを入れ替えたあとに押した場合は、既に切り替わっていることを伝えたうえで、
  **ゲームの起動だけは止めます**

### 待ちが必ず終わる仕組み

待ちはすべて `SwitchTask.pause()` を通します。そこで3つをまとめて見張っています。

| 見張るもの | 動き |
|---|---|
| 取り消し | 押された瞬間に畳む |
| Riot Client の生死 | 0.5秒ごとに確認。**続けて6回（約3秒）**見えなければ中止 |
| 全体の締め切り | `DEADLINE_SEC = 300` 秒で打ち切る |

- クライアントの生死監視は、**アプリが自分でクライアントを起動したあと**から始まります
  （それ以前は監視しません）
- 「続けて6回」という猶予を置いているのは、Riot Client が**自己アップデートで一度
  自分を落として立ち上げ直す**ためです。1回消えただけで打ち切ると、成功するはずの
  切り替えを捨ててしまいます

さらに、万一 `pause()` の外で戻ってこなくなった場合に備えて、**締め切り＋30秒で
操作だけを取り返す**見張りを別に持っています（スレッドは放置し、トレイ操作だけ復帰させます）。

> 以前はこの処理が UI スレッドの上で直接走っていて、待ちの一部が生の `time.sleep`
> だったため、**最悪90〜190秒アプリが完全に固まり**、「終了」にも手が届きませんでした。
> クライアントが落ちても誰も見ていなかったので、全部のタイムアウトを使い切るまで
> 戻ってきませんでした。

## 自動ログイン

保存済みのセッションが無効だったときに走ります。

### いつ「無効」と判断するか

- 控えのトークンが空同然（1000バイト未満）なら、**待たずに**ログイン画面へ進みます
- クライアントの起動を最大40秒待ちます
- ただし**ローカル API が答え始めたら、認証はもう済んでいます**（実測で差 0.00〜0.76秒）。
  そこから **4秒**待っても認証されていなければ、ログイン画面で止まっているとみなします
- `/app-command/v1/auth/status` が `Failed` を返したら、待たずに打ち切ります
- トークンを消す直前に**もう一度だけ**確認します（遅れて認証が通っていた場合に、
  有効なトークンを消さないため）

> 以前はここで40秒を丸ごと使い切っていたので、自動入力が始まるまでが長く感じました。

### どうやって入力するか

2つの方式があり、上から順に試します。

1. **UI Automation** — 入力欄に値を直接セットします。キーを撒かないので確実ですが、
   **今の Riot Client は画面の中身をアクセシビリティに公開しない**ため通りません。
   UI 要素が15個未満のまま2回走査した時点で見切りをつけます（実測では毎回7個）
2. **キー入力** — `pyautogui` で ID → Tab → パスワード → Tab×6 → Enter → Tab → Enter と打ちます

**キー入力でも他アプリへの誤爆は起きません。** Riot Client を前面にできたことを
**打ち始める前に2回**（前面化した直後と、1.2秒待ったあともう一度）確かめ、
確認できなければ入力そのものを中止するためです。

#### 効かないと分かったら覚える

UI Automation が使えないと分かったら `settings.json` の `"uia_probe"` に記録して、
次からは飛ばします。ただし次のどちらかで**試し直します**。

- Riot Client の実体が変わったとき（更新日時とサイズで判定）
- 前回の確認から1週間たったとき

Riot 側が公開を再開すれば、自動でまた使われるようになります。

## PUUID の自動記録

`.env` に API キーがあれば、**登録済みの全アカウントについて PUUID を自動取得し、
メモに追記**します。起動の数秒後と、一覧を開いたときに走ります。

- 一度取得した PUUID はアカウントに保存され、**以後 PUUID のためだけには API を叩きません**
  （ランクのキャッシュが切れたアカウントは、ランク取得のついでに API を叩きます）
- ランクのキャッシュが新しくても、PUUID が無ければ PUUID だけ取りに行きます
- 既にメモに載っていれば何もしません。メモの既存の内容は消しません
- 保存済みの PUUID がメモから消えていた場合は、**通信せずに**書き戻します
  （こちらは論理削除したアカウントも対象です）
- API から取りに行く対象からは、論理削除したアカウントを除きます

## 並べ替え

アカウント名を**長押しするとその行が浮き上がり**、上下に動かして並べ替えられます。
浮いた行が抜けた跡には隙間ができ、他の行がその場で譲って上下に動きます。
離した時点で `settings.json` に保存され、次回起動時もその並びになります。

- 長押しの判定は **0.22秒**です（動かし始めれば待たずに浮きます。動かし始めの
  しきい値は Windows 側の設定に従います）
- 浮いた行は**見えている位置にそのまま着地**します（1行ぶん動かせば1つ移動）
- 少し動かしただけはクリック扱いのままなので、**掴もうとしてうっかりアカウントが
  切り替わることはありません**
- 浮かせた後は、動かさずに離しても切り替わりません（並べ替えの取り消しになります）

## 新規アカウント追加の流れ

1. 一覧下部の「**＋ アカウントを追加**」から ID / パスワードを入力
2. 既存の Riot プロセスを終了
3. **今のログイントークンを削除**（ログイン画面を出すため）
4. Riot Client を起動し、ログイン画面へ自動入力
5. ログインできたか、ローカル API で Riot ID が取れるまで最大15秒待つ
6. 取れたら、セッションを `Profiles/<RiotID>` へ保存し、`settings.json` に登録
   （パスワードは暗号化して保存。ゲームは起動しません）

> 追加中もトレイから中止できます。ただし**3で消したトークンの控えを取るのは
> 切り替えの経路だけ**で、追加の経路では取りません（もともと別のアカウントで
> ログインし直すのが目的のため）。

## 設定・データの保存場所

すべて `%LOCALAPPDATA%\Switch\` 配下です（exe の場所に依存しません。ただし `.env` だけは
exe の隣も見ます）。

```
%LOCALAPPDATA%\Switch\
├── settings.json      … アカウント情報・PUUID履歴・ランクキャッシュ・各種設定
├── settings.json.bak  … 保存のたびに作られる、直前の内容
├── license.dat        … ライセンス認証の結果キャッシュ
├── .env               … （任意）APIキー
├── debug_log.txt      … 診断ログ（MENUから開ける）
├── cpu_watchdog.log   … CPU監視ログ（既定はOFF）
└── Profiles\
    └── <RiotID>\      … アカウントごとのセッションファイル一式
```

`settings.json` は MENU の「**設定（メモ帳）**」から直接編集できます。

### settings.json のおもなキー

| キー | 既定 | 意味 |
|---|---|---|
| `login_accounts` | — | アカウントごとの ID・暗号化パスワード・メモ・ランクキャッシュ |
| `theme` | `"light"` | ライト / ダーク |
| `click_launch` | `true` | クリックでゲームまで起動するか |
| `uia_probe` | — | UI Automation が使えたかの記録 |
| `puuid_history` | — | PUUID ツールの履歴 |
| `cpu_watchdog` | `false` | CPU監視を動かすか |
| `cpu_watchdog_threshold` | `25` | 記録するしきい値（**1コア換算の%**。100 = 1コアぶん使い切り） |

### 入れ替えているファイル

切り替え時に、`Profiles\<RiotID>\` と Riot Client の実データの間でコピーします。
右側の相対パスは、`%LOCALAPPDATA%\Riot Games\Riot Client\` からの相対です。

| 控え側のファイル名 | 実機側の相対パス |
|---|---|
| `RiotGamesPrivateSettings.yaml` | `Data\RiotGamesPrivateSettings.yaml` |
| `Sessions`（フォルダ） | `Data\Sessions` |
| `RiotClientSettings.yaml` | `Config\RiotClientSettings.yaml` |

自動ログインには「**サインイン状態を維持**」がONである必要があります
（永続トークンが `RiotGamesPrivateSettings.yaml` に保存され、次回以降の切り替えが成立します）。
UI Automation で入力できた場合は自動でONにしますが、キー入力の場合は
打鍵の順番でチェックボックスへ到達しています。

### CPU監視（既定OFF）

`settings.json` の `"cpu_watchdog"` を `true` にして再起動すると、自プロセスのCPU使用率を
5秒ごとに見張り、しきい値を超えた瞬間の全スレッドのスタックを `cpu_watchdog.log` に残します。
常駐中ずっと定期的にスレッドを起こすので、**不具合を追いたい時だけ**ONにしてください。

## データを失わないための作り

アカウント情報とパスワード、セッションファイルは他に控えがありません。壊さないための備えです。

### セッションファイルの入れ替え

- **元が無いものは、行き先に指一本触れません。** 以前は「行き先があれば消す」と
  「元があればコピー」を別々に判定していたので、元が無いときに**行き先だけが消えて**いました
  （控えが空のまま切り替えると実機の `Data\Sessions` が消え、実機に `Sessions` が無いまま
  保存すると控えが消えます）
- 「控えがあるか」の判定は、**フォルダの有無ではなく中身の有無**で見ます
- 切り替え先の控えが空でマクロログインへ回る場合、**トークンを消す前に今のログイン情報の
  控えを取ります**。取り消したりログインに失敗したら、元に戻します

### settings.json

- 保存は**一時ファイルへ書いてから置き換え**ます。途中で失敗しても半端なファイルは残りません
- 置き換える前の内容は `settings.json.bak` に残ります
- **読み込みに失敗しても、空の設定を「最新」として記録しません。** 直前に読めた内容を
  使い続け、ファイルが直れば次の読み込みで復帰します
- **アカウントが空の状態で、既存の設定ファイルを上書きしません。** 手で編集して JSON を
  壊しても、直せる状態のまま残ります
- 保存に失敗したときは、成功したように振る舞いません（ログに残ります）
- 切り替えが別スレッドになったので、読み書きには鍵をかけています

## デザイン

UIは `DESIGN.md`（Apple スタイルリファレンス）に沿っています。

- 本文は **12px**、見出しは 9px、補助的な文字は 10〜11px
- 角丸は 3 / 5 / 8 / 14px を使い分け（行やボタンの角丸は、高さの半分を超えないよう
  実際の行の高さから計算しています。超えると Qt は丸めを諦めて直角に描くため）
- 境界は 1px のヘアラインと面の色差で作り、**影は原則として使いません**。
  例外は「掴んで浮かせた行」と「アカウント一覧のウィンドウ」の2か所だけで、
  前者は掴んでいる間の一時的な手応えとして意図的に付けています
- アクセントは `#0071e3`。塗りボタンの背景、ログイン中の点、トーストの「取り消し」に使います

### 書体

同梱の **Rounded Mplus 1c**（`assets/fonts/`、OFL）を使います。配布先PCに入っていなくても
同じ見た目になります。太字は Bold(700) ではなく **Medium(500)** です
（この文字サイズだと Bold は漢字が潰れるため）。

#### 文字の描画（FreeType）

Windows 標準の描画だと、暗い面の上で文字の縁に色が乗って荒れて見えます
（サブピクセル描画のため。実測で文字の画素の75.3%に色が乗っていました）。
起動時に `QT_QPA_PLATFORM=windows:fontengine=freetype` を設定してグレースケール描画にしています
（実測 0.0%）。

### ライト / ダークモード

MENU のトグル、または行のどこを押しても切り替わります。選択は `settings.json` の
`"theme"` に保存され、次回起動時も引き継がれます。

- 色は QSS の差し替えで一斉に変わります。切り替えの瞬間は、直前の見た目を写した画像を
  重ねて**約0.42秒かけて溶暗**させるので、パッと入れ替わりません
- そのときトグルの部分だけは重ね画像から消してあります（トグルは本物が動くため）
- ダークモードのトグルは、つまみが**三日月に変形**し、トラックが夜空の色になり、
  星が3つ上から降ってきます

## ソースから実行

```bash
python main.py
```

ソース実行では、`print` の出力は**そのままコンソールに出ます**。診断ログ
（`debug_log.txt`）へ書き出すのはビルド版だけです（画面が無いため）。

## ビルド（単一 exe を作成）

[PyInstaller](https://pyinstaller.org/) を使用します。

```bash
pip install pyinstaller
pyinstaller main.spec
```

- 出力: **`dist\スイッチ.exe`**（onefile・単一ファイル）
- アイコン（`assets\icon.ico`）と同梱フォントは exe に含まれます
- 生成された exe は**任意の場所に移動して動作**します
- 起動を速くするため `requests` / `urllib3` / `shutil` / `traceback` は遅延読み込みに
  しています。PyInstaller が静的に追えないので、`main.spec` の `hiddenimports` に
  並べてあります（消すと動かなくなります）

## 診断用フラグ

exe でもソースでも使えます。どちらも画面を出さずに結果をファイルへ書き出します。

```bash
スイッチ.exe --uia-selftest     → %TEMP%\switch_uia_selftest.txt
スイッチ.exe --font-selftest    → %TEMP%\switch_font_selftest.txt
```

- `--uia-selftest` は `uiautomation` が読み込めてデスクトップのルート要素を取れるかだけを
  見ます（**Riot Client の中身が読めるかまでは見ません**）
- `--font-selftest` は同梱フォントが実際に使われているか、文字がグレースケールで
  描かれているか（＝FreeType が効いているか）を見ます
